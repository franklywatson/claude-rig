# Behavioral Eval Harness Implementation Plan

> **Status:** Executed — shipped in PR #45 / commit df0313e; full evals/ tree live; archived 2026-06-17


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Task 1 is a make-or-break spike with a STOP condition — do not build Tasks 2+ until it passes.**

**Goal:** A local `npm run eval` harness that drives scripted `claude -p` sessions against fixture project briefs and asserts on skill-chain *behavior* the deterministic suite cannot reach (does `brain+` fire the loop opt-in for a fitting project and stay silent for a CLI tool; does an opted-in design contain the required sections), with model-robust invariants so a Fable-vs-Opus diff surfaces behavioral drift. Spec: `docs/superpowers/specs/2026-06-12-eval-harness-design.md`.

**Architecture:** New top-level `evals/` dir (TypeScript run via `tsx`, never shipped in `dist`, excluded from `npm test`). A runner scaffolds a temp project → `rig init` → drives `claude -p --model <m> --output-format stream-json` → captures transcript+artifacts → grades structurally (concept-token sets + artifact checks, one confined judge fallback) → N-of-M majority → `EvalReport` (mirroring `tests/eval/score.ts`) → teardown. The harness's pure logic is unit-tested under `tests/evals/` with canned recorded transcripts; the live `claude -p` driver is injected (`DriveSessionFn`) so units never hit the network.

**Tech Stack:** TypeScript, vitest (units only), tsx (runner), commander-style arg parse, the `claude` CLI (`-p --model --output-format stream-json`).

## Mock Policy

No mocking frameworks. The runner takes an injectable `DriveSessionFn` (the rig `ExecFn` convention): unit tests pass a **canned recorded transcript**; live runs pass the real `claude -p` driver. Canned transcripts are real recorded `stream-json` output (real dependencies, not fabricated mocks).

### Task 1: SPIKE — does `claude -p` invoke a skill headlessly, and can we capture it?

**Files:** Create `evals/spike-findings.md` (+ a throwaway `evals/spike.ts`, deleted at task end)
**Test strategy:** empirical — this task's "test" is the recorded real-run evidence; no unit tests.
**Mock check:** none (live `claude -p`).

> This resolves the spec §7 make-or-break unknown: skills are normally invoked via the Skill tool in an *interactive* session. It is unproven that `claude -p "...use /brain+..."` auto-invokes the skill non-interactively. Everything downstream assumes it does.

- [ ] **Step 1: Scaffold a probe project.**

```bash
PROBE=$(mktemp -d /tmp/rig-eval-spike-XXXXXX)
cp -r templates "$PROBE/" 2>/dev/null || true   # not needed; use rig init
( cd "$PROBE" && rig init >/dev/null 2>&1 )
printf 'I want to build a headless scheduled service that scores inbound applicants nightly by calling an external ATS API. Design it.\n' > "$PROBE/BRIEF.md"
ls "$PROBE/.claude/skills/" | head
```

Expected: `.claude/skills/` contains `brain-plus` etc.

- [ ] **Step 2: Drive a headless brain+ run and capture stream-json.**

```bash
cd "$PROBE" && claude -p "Read BRIEF.md, then use the /brain+ skill to begin designing this. Ask me your first clarifying question." \
  --model "$(node -p "process.env.EVAL_MODEL||'claude-opus-4-8'")" \
  --output-format stream-json --verbose > "$PROBE/transcript.jsonl" 2>"$PROBE/err.log"
echo "exit=$?"; wc -l "$PROBE/transcript.jsonl"
```

- [ ] **Step 3: Inspect — did the skill load, and is its output in the transcript?** Record in `evals/spike-findings.md`, verbatim, the answers to:
  1. Did the transcript contain evidence the `brain-plus` skill loaded (its instruction text / a `Skill` tool call / the loop opt-in framing)?
  2. Is assistant text recoverable from the `stream-json` lines (which JSON field)?
  3. Did any artifact get written to the probe dir, or does brain+ stay conversational on turn 1?
  4. Did the run terminate on its own (headless, single prompt) or hang waiting for input?

- [ ] **Step 4: STOP-gate.** If Step 3 shows the skill did **not** auto-invoke, or the transcript carries no recoverable assistant text, **STOP and report NEEDS_CONTEXT** with the findings and these fallback framings to weigh before building:
  - (a) make the prompt explicitly instruct skill use and assert on the *response*, not auto-invocation;
  - (b) retarget the eval at observable rig outputs that need no skill auto-invoke (session-start panel content, router decisions on real commands) — narrower but robust;
  - (c) drive a multi-turn `--input-format stream-json` exchange to reach the opt-in question.
  If Step 3 passes, record the working invocation + the JSON field carrying assistant text (the grader will key on it) and proceed.

- [ ] **Step 5: Capture a canned transcript for unit fixtures, then clean up + commit.**

```bash
cp "$PROBE/transcript.jsonl" evals/fixtures/canned-loop-fit-positive.jsonl   # real recorded output for unit tests
rm -f evals/spike.ts
rm -rf "$PROBE"; rm -f /tmp/rig-session-*  # only spike's; verify by mtime before rm
git add evals/spike-findings.md evals/fixtures/canned-loop-fit-positive.jsonl
git commit -m "spike: prove claude -p skill invocation + transcript capture for the eval harness"
```

### Task 4: Structural grader + matchers (the model-robustness core)

**Files:** Create `evals/grade.ts`; Test `tests/evals/grade.test.ts`
**Test strategy:** unit matchers run over **canned transcripts** (the Task 1 capture + a hand-built negative sample) — real recorded output, no fabrication.
**Mock check:** none (canned real transcripts are the inputs).

> **Model-robustness rationale (locked):** `brain+`'s opt-in question (template lines 64–66) contains `agent-loop pattern` and `maintainer trajectory`. The token `signal stack` ALSO appears in brain+'s general signal-first guidance (line 45) that runs for *every* project — so keying on `signal stack` would false-positive the negative scenario. The grader keys the loop-opt-in invariant on the **loop-specific tokens** `agent-loop pattern` / `maintainer trajectory` (case-insensitive, either present), never `signal stack`.

- [ ] **Step 1: Failing tests** `tests/evals/grade.test.ts`:

```typescript
import { describe, it, expect } from 'vitest';
import { readFileSync } from 'fs';
import { extractAssistantText, matchLoopOptIn, matchSectionsPresent } from '../../evals/grade.js';

const positive = readFileSync('evals/fixtures/canned-loop-fit-positive.jsonl', 'utf-8');

describe('grade: loop opt-in detection (model-robust tokens)', () => {
  it('detects the opt-in via loop-specific tokens', () => {
    const text = extractAssistantText(positive);
    expect(matchLoopOptIn(text)).toBe(true); // agent-loop pattern / maintainer trajectory present
  });
  it('does NOT fire on a transcript that only mentions the ambient "signal stack" guidance', () => {
    const ambient = 'We considered which layers of the signal stack this CLI touches. It does not fit a loop.';

  });
});
```
